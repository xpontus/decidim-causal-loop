# Deploying a small Decidim instance with the causal loop module

These files set up a Decidim 0.31.3 instance with this module on one Ubuntu
server, for a group whose accounts an administrator creates:

- Decidim runs natively (Ruby and Node through [mise](https://mise.jdx.dev/),
  PostgreSQL from the distribution).
- Puma listens on `127.0.0.1:3000` only, and [Caddy](https://caddyserver.com/)
  terminates TLS in front of it.
- The instance sends **no e-mail**. Registration is limited to existing users,
  and the administrator creates accounts with generated passwords and hands
  them out.
- The site is private by default: visitors must log in to read anything.

The server installs from a git clone of this repository, never from a copied
working tree, so every installation also tests these instructions and every
deployed state is a commit. The clone can come from GitHub, or from a bare
repository on the server that a development machine pushes to (see
[Deploying from a development machine](#deploying-from-a-development-machine)).
Secrets are generated on the server and stay there.

| File | Purpose |
|---|---|
| `install_host_app.sh` | generates the Decidim host app next to the module and configures it |
| `files/` | configuration copied into the host app: no e-mail, Puma on loopback, Action Cable without Redis, a Decidim search fix |
| `make_env.sh` | writes the environment file with a new `SECRET_KEY_BASE` |
| `setup_organization.rb` | system administrator, organization, first administrator, optionally a process with a diagram |
| `create_user.rb` | adds a participant, administrator or diagram editor; resets passwords |
| `update.sh` | deploys a branch (default `main`): fetch, migrate (after a database dump), rebuild assets, restart |
| `decidim.service` | systemd user unit for Puma |
| `Caddyfile.example` | reverse proxy |

## Layout

Everything lives in one directory owned by the user who runs Decidim. The
examples use `/opt/rurbanive`:

```
/opt/rurbanive/
├── decidim-module-causal_loop/   clone of this repository
├── decidim_app/                  generated by install_host_app.sh
├── decidim.env                   secrets (mode 600), from make_env.sh
└── backups/                      database dumps made by update.sh
```

The module and the host app must be siblings, because the host app's
Gemfile refers to the module as `path: "../decidim-module-causal_loop"`.

## 1. System packages (sudo)

```bash
sudo apt install git curl build-essential libssl-dev libyaml-dev zlib1g-dev \
  libffi-dev libpq-dev postgresql imagemagick caddy
sudo -u postgres createuser "$USER"
sudo -u postgres createdb -O "$USER" decidim_production
sudo mkdir -p /opt/rurbanive && sudo chown "$USER": /opt/rurbanive
```

The packages cover compiling Ruby, the PostgreSQL client library, and image
variants (Decidim uses MiniMagick). The database role has the same name as
the Unix user, so Rails connects over the local socket with peer
authentication and needs no password.

## 2. Ruby and Node (no sudo)

```bash
curl https://mise.run | sh          # installs ~/.local/bin/mise
~/.local/bin/mise install ruby@3.3.11 node@22.14.0
```

Non-interactive shells (ssh commands, systemd) do not activate mise. Prefix
commands with `mise exec ruby@3.3.11 node@22.14.0 --`. Below, `m` is a shell
function for that prefix (works in bash and zsh):

```bash
m() { "$HOME/.local/bin/mise" exec ruby@3.3.11 node@22.14.0 -- "$@"; }
```

## 3. Host app

```bash
cd /opt/rurbanive
git clone https://github.com/xpontus/decidim-causal-loop.git decidim-module-causal_loop
cd decidim-module-causal_loop
m deploy/install_host_app.sh       # ~10 minutes: generator, gems, npm
```

The script refuses to run if `decidim_app` already exists. It checks that
every migration carries a `.decidim*` suffix; Decidim's own migrations and
ActiveStorage's would otherwise collide.

## 4. Database and first start

```bash
deploy/make_env.sh                  # → /opt/rurbanive/decidim.env
cd ../decidim_app
set -a; . ../decidim.env; set +a
m bin/rails db:migrate
m bin/rails assets:precompile
```

Then create the organization. `HOST` is the name people will type in the
browser. Decidim recognises the organization by the `Host` header and
redirects secondary hosts to the main one, so a name without a DNS entry
cannot be reached through a secondary IP address. Until DNS works, use the
server's IP address as `HOST`, and change it to the name later at `/system`
(Organizations → Edit) together with the Caddyfile.

```bash
SYSTEM_ADMIN_EMAIL=you@example.org ADMIN_EMAIL=you@example.org ADMIN_NAME="Your Name" \
ORG_NAME="My project" PROCESS_TITLE="Causal loop" \
  m bin/rails runner ../decidim-module-causal_loop/deploy/setup_organization.rb HOST
```

It prints the generated passwords once. The system administrator logs in at
`/system`; it is a separate account from the organization administrator,
even with the same e-mail address. Decidim asks administrators to accept the
admin terms on their first visit to the admin panel.

## 5. Run Puma as a service

```bash
mkdir -p ~/.config/systemd/user
cp ../decidim-module-causal_loop/deploy/decidim.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now decidim
sudo loginctl enable-linger "$USER"     # once, sudo: keep it running after logout
curl -sI http://127.0.0.1:3000/ | head -1   # 301 to https (force_ssl)
journalctl --user -u decidim -f         # logs
```

A user unit means `update.sh` can restart Puma without sudo.

## 6. Caddy (sudo)

```bash
sudo cp ../decidim-module-causal_loop/deploy/Caddyfile.example /etc/caddy/Caddyfile
sudoedit /etc/caddy/Caddyfile           # host name; "tls internal" until public DNS works
sudo systemctl reload caddy
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
```

## Accounts

```bash
cd /opt/rurbanive/decidim_app && set -a; . ../decidim.env; set +a
u() { m bin/rails runner ../decidim-module-causal_loop/deploy/create_user.rb "$@"; }
u anna@example.org "Anna Andersson"                  # participant
u anna@example.org "Anna Andersson" --editor 3       # … who may edit diagram (component) 3
u bo@example.org "Bo Berg" --admin                   # organization administrator
u anna@example.org --reset                           # new password
```

Passwords are generated (20 characters) and printed once. Without e-mail,
nobody can reset their own password: run `--reset` and hand over the new one.
Organization administrators and the process's administrators can edit every
diagram. Others need `--editor`, or the component's **Manage → Diagram
editors** page.

## Updates

After a change is pushed to `origin`:

```bash
cd /opt/rurbanive/decidim-module-causal_loop && m deploy/update.sh            # main
cd /opt/rurbanive/decidim-module-causal_loop && m deploy/update.sh my-branch  # another branch
```

It refuses to run if the checkout has local changes, because code is never
edited on the server. It dumps the database to `backups/` before migrating.

## Deploying from a development machine

To test changes on the server without publishing them, let the server's
checkout follow a bare repository on the server instead of GitHub, and push
to it over ssh. In step 3, replace the `git clone` from GitHub with:

```bash
git init --bare /opt/rurbanive/causal_loop.git
```

On the development machine (`myserver` is its ssh name):

```bash
git remote add server myserver:/opt/rurbanive/causal_loop.git
git push server main                    # or any branch
```

Then on the server:

```bash
cd /opt/rurbanive
git clone causal_loop.git decidim-module-causal_loop
```

From then on, deploy with `git push server <branch>` and
`m deploy/update.sh <branch>` on the server. Only committed changes reach the
server; commit work in progress on a branch to try it.

## Maintenance

Deleted variables and links are kept for undo. To purge those older than
30 days, add a daily job to the user's crontab (`crontab -e`):

```
15 3 * * * cd /opt/rurbanive/decidim_app && set -a && . ../decidim.env && set +a && $HOME/.local/bin/mise exec ruby@3.3.11 -- bin/rails decidim_causal_loop:purge_deleted
```

## AI assistant

Configured in `decidim.env`; see the module README. With no provider
configured and no Ollama reachable on `localhost:11434`, the assistant
answers 503 and the rest works normally. Restart after a
change: `systemctl --user restart decidim`.
